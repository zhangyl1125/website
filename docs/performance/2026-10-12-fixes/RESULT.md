# 奖项页性能修复与复核记录

本次完成资源完整性、奖项页请求以及并发会话续期修复；共享环境中的间歇性 API 超时仍存在，不能宣称卡顿已经全部解决。

**修复内容**

- 完整字体：重新生成两份 Noto Sans CJK SC 字体，并增加 Latin 子集与资源版本号，避免继续读取旧的损坏缓存。字体族、字重、颜色、布局和原有字符覆盖范围保持一致；仅西文内容的最初两份子集共 37,476 字节（后续纳入标点后为 43,640 字节），出现其他字符时仍加载完整字体，不能把整页字体下载量一概称为 37 KB。
- 完整视频：从同一视频的完整备份恢复，保留 1920×1080、30fps、16 秒及循环播放，480 帧全部可解码。压缩结果 3,483,420 字节；与 8,293,954 字节完整原素材比较减少约 58%，SSIM 约 0.9892。不能与原先被截断的 2.3 MB 文件比较压缩收益。
- 奖项加载：管理员列表不再逐个查询每个活动的评委；管理详情只查询当前活动评委。普通评委用现有分配接口筛选可见活动，保持后端权限校验。浏览器模拟管理员看见 2 个测试活动、普通评委仅看见其分配的 1 个活动，两者列表均不再发出逐活动评委查询。
- 会话续期：多个请求同时 401 时共享同一个进行中的续期请求。新增用例在修复前复现 2 次续期、修复后只有 1 次；保留原接口重试、实际业务错误返回和续期失败退出行为。
- 代理：启用 API 上游连接复用，增加只记录路由类别和耗时的诊断日志。日志不记录请求正文、查询参数、Cookie、Authorization 或原始路径中的邀请令牌。这项配置尚未证明能消除当前超时。

**功能与界面边界**

最初的独立候选构建曾使用原页面 JSX/CSS，避免带入当时工作区尚未发布的界面改动。检查期间其他部署多次替换了前后端镜像，因此该候选镜像和 `release-manifest.json` 只代表当时的验证快照，**不是当前线上版本的完整描述**。后续以当前 80 端口实际服务为准，没有用旧候选镜像覆盖其他部署的新页面。

2026-10-12 后续又完成了标点字体分包，详见 [FOLLOWUP.md](FOLLOWUP.md)。此次只更新字体资源和 CSS 字体声明，不更改当前页面脚本、布局、颜色、投票计分或权限规则。

- 最终发布目录：奖项页和 API 客户端 19 项针对性测试通过。

- 修正过期测试：邮箱选择器不再匹配“记住邮箱”复选框；概览测试匹配当前英文按钮；提名测试先完成现有裁剪确认步骤。没有为了让测试通过而改变页面功能。

- 隔离浏览器：字体全部成功解码，视频成功循环，管理员/普通评委可见范围正确，无脚本错误。第一次跳播循环断言曾超时，记录缓冲状态后的复测通过；不将此宣称为跨设备长期播放稳定性保证。

**仍存在的问题与定位边界**

20 次低频采样中，旧端口 80、候选端口 18081、直连 8080 均返回成功，最大耗时分别约 8.29、8.34、7.54 ms。但候选版更密集的 10 客户端测试，130 次读取中发生 10 次约 2 秒超时，按保护条件停止升压，未继续 50 客户端阶段。

进一步对旧版和修复版同时施加相同的小规模负载：两边各 155 次请求、各 5 次超时，P95 分别 5.64/5.55 ms。两边同步停顿，说明该现象不是本次前端修复或连接复用配置独有的回归。不能把没有报错的短时窗口当作持续容量，也不能由此宣称支持多少真实在线用户。

候选代理日志显示：超时时 `upstream_connect_time` 为 0～1 ms，`upstream_header_time` 为 `-`，客户端截止后记录 499。即已完成连接，但未及时收到上游响应头。主机 I/O 压力多次明显偏高，不过目前缺少能够证明具体阻塞来源的完整关联证据。

曾使用 Java SIGQUIT 获取一次线程栈，没有停止或重启 API；采样时线程以空闲或正常执行为主，未发现明确的连接池死锁。线程转储本身可能干扰延迟，不能把转储期间的直连超时当作独立的根因证明。此后确认 API 恢复毫秒级响应、重启次数为 0。没有盲目增加线程/连接池，没有停止其他项目，也没有改动宿主机磁盘或系统参数。

后续定位应采集同一时间段的 JVM 停顿、数据库等待、Docker/宿主机磁盘延迟和容器网络，必要时在独立资源环境对照复现。缺乏这些证据时，不能承诺网站卡顿已完全消除或给出可靠的稳定在线人数上限。

**回滚边界**

`hackhub-app:before-performance-20261012` 是早期保存的镜像。其他部署已更新过前后端，不能直接用这个旧镜像覆盖当前站点，否则可能丢失后来发布的功能。标点字体更新使用独立 CSS 文件并保留旧文件，回退时应先核对 `font-deployment.json` 的容器 ID 和 HTML 哈希，再只还原 CSS 引用。源码修复需保留在后续构建中；复用旧镜像重建容器会丢失仅写入容器的静态资源更新。后续已确认新部署镜像本身包含此次字体修复，见 `final-live-version.json`。
